사이드뷰의 의미

강의실 SCENE 자체는 심플 (책상+칠판+학생). 카드 뒤집기마다 칠판 텍스트가 분해 애니로 바뀌는 것이 주된 시각 변화.

왜 카드를 게임뷰 안에 안 넣는가

게임뷰 = 분위기. UI영역 = 인터랙션. 분리해야 카드 텍스트 가독성 + SRS 4버튼 터치영역 확보.

카드 ↔ 도감 연동

"쉬움" 등급 → 어원 도감에 자동 등록(애니메이션) → ⑤ 도서관 인벤토리에 새 어원 블록 등장.

왜 모달인가 (모드 진입은 풀스크린이라며)

씬 전환 ≠ 결과 피드백. 도서관 안에서 정답·오답 결과는 연속 플레이를 위해 모달이 자연스러움. 새 챕터/씬 이동만 풀스크린.

제시어 → 영문 매칭 vs 영문 → 한글

초기엔 한글→영문 조립(생산형). 챕터 후반/병동에서 영문→한글 인식(소비형). 두 방향 다 학습 필요.

실패 처리

오답 → SRS 큐 자동 등록 + 힌트 1개 자동 노출 + 재시도. 3회 실패 시 정답 공개 후 다음 문제.

차트의 증상(한글)을 의학용어(영문)로 답하면 데미지. 정답 = 증상에 취소선. 전 증상 클리어 = HP 0 = 진료 완료.

오답 페널티

환자 턴 → 의대생 HP −15. 0 되면 "후송"(=재시도). 너무 가혹하지 않게 SRS 자동 등록만 하는 안도 검토.

⚠ 톤 위험

"환자 = 몬스터"는 의대생 정서에 거부감 가능. "질병 = 적, 환자 = 보호 대상"으로 프레이밍 + HP가 줄면 "회복" 표현으로 베타 검증 필요.

"같은 학과 친구가 위에 있다" = 가장 강한 동기. 닉네임을 실명 인접하게 만드는 컨벤션 유도(필명 권장하되 실명 아바타와 매칭 가능). 단, 익명성 보호 옵션 필수.

표시 정책
  • 주간 XP만 (누적 X) → 신규 유저 진입 장벽 ↓
  • 닉네임 검열 + 신고 기능
  • 내 위치 항상 sticky로 노출
위험
  • 1등 박탈감 → 학과 평균/구간 평균 동시 노출로 완화
  • 치팅(자동화) → 일일 XP 캡 + 비정상 패턴 감지

왜 응급실 시점에 게이트

D+7~14 = 무료 콘텐츠로 충분히 학습 효과 체감 후. 너무 일찍 = 거부감, 너무 늦으면 = 결제 동기 ↓.

학기 패스를 디폴트 ★로

학생 학기 단위 = 결제 직관적. 24% 할인으로 LTV ↑. 단, 해지/환불 정책 명확히 + 학생 인증 −20% 이중 할인.

모바일 특화 결정 (데스크탑과 다른 점)
  • 캠퍼스맵 = 사이드뷰 1축 스크롤 (데스크탑 = 탑다운 그리드). 모바일에서는 좌우 스와이프가 가장 직관적.
  • 응급실 = 카드 스택 ↔ 단일 진료 2화면 (데스크탑 = 4베드 그리드). 모바일은 동시 노출 불가능 → 트리아지 별도 화면.
  • 하단 4탭 네비게이션 = 캠퍼스/도감/랭킹/설정. 캠퍼스맵 자체가 강의실/도서관/병동 진입점이라 "홈" 탭 불필요.
  • UI 비율 60/40 위/아래 고정. 게임뷰가 너무 작으면 픽셀 매력 소실, 너무 크면 SRS 4버튼 터치영역 부족.
  • 플래시카드 = 게임뷰 위 칠판 + 아래 카드. 게임뷰 안에 카드를 넣지 않음(가독성).
미해결 / 베타 검증 필요
  • 병동 톤 — "환자 = HP 줄이기" 메타포가 의대생 정서에 거부감? "질병 = 적, 환자 = 회복" 프레이밍 필요.
  • 가로모드 — 사이드뷰 게임은 가로가 자연. 세로 강제 vs 가로 회전 시 데스크탑 레이아웃 재사용?
  • 가상 D-패드 누락 — 자동이동 + 탭으로 충분한가? RPG 매니아 사용자에겐 부족할 수 있음 (옵션 토글).
  • SRS 위치 — 캠퍼스 진입 시 강제 복습 vs 사용자 선택? 이탈률 차이 측정.
  • 접근성 — 픽셀폰트 가독성, 색약 (HP 빨/녹), 텍스트 모드, 음성 발음.
  • 오프라인 — 지하철/이동 중 학습 = 모바일의 핵심 컨텍스트. 로컬 SRS 큐 + 동기화 충돌 처리.
